# Retail demo workspace

The retailer demo uses the production retailer sign-in and the real `RetailApp` at `/retail`. It does not use a separate portal, client-side password check, or browser-only sample records. The guide appears only after Supabase verifies the dedicated retailer account at `demo@getmacrostack.com`; closing it leaves the user in the live portal, and **Replay tour** is available in the header.

The demo account belongs only to a dedicated **MacroStack Retail** organization with two sample locations and fictional customer records. Sample customer email addresses use the reserved `example.com` domain. One fictional personal account is linked to the Jordan Lee sample relationship so the real nutrition plan and food journal screens can be explored. Do not link a real customer's account to a sample relationship. Both locations are non-billing. The demo account cannot send retailer invitation emails or open Stripe billing; these restrictions are enforced in the Edge Functions as well as the portal.

The dedicated account is email-confirmed and has Supabase Auth app metadata `account_type=retailer` and `retail_verified_email=demo@getmacrostack.com`. It has active organization-administrator and location-level manager memberships. These are production configuration records, not application seed data; do not store account passwords, Supabase service keys, or database contents in Git. The current demo organization ID is `43ae3323-3c3a-4c81-a703-b56b74545535`. Only this organization should hold the fictional sample records.

After provisioning, verify sign-in at `/retailers?signin=1`, the redirect to `/retail`, the guide on the actual Today/Customers/Inbox/Resources/Store screens, Back/Next/close/replay behavior, and data isolation from other retailer organizations. Revisit the shared sample records periodically because visitors can change demo data while exploring.
